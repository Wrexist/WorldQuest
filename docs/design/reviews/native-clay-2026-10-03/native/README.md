# iOS simulator evidence

Latest bounded check: normal-entry run [37128874643](https://github.com/Wrexist/WorldQuest/actions/runs/37128874643), commit `5485decaed70336b77fe75ad42dea5459ae6c2de`, tested the synchronous onboarding guard on an iPhone 16 Pro simulator with iOS 18.5 and both diagnostics disabled. **Both independent fresh installations rendered Atlas, island and clouds correctly.** The direct first quiz, optional Learn first screen, return to quiz, Pause/Finish here, Home and persisted Home after relaunch passed. The four answer cards were visible; the optional study heading and Back to quiz action cleared the system insets. Static globe images in the quiz and region choices rendered correctly. This supports removal of the measured startup trigger, not a general React Native image-callback or physical-device performance claim.

That run stopped at Explore before the live globe or country links could be verified. The reference-content gate displayed its recoverable error state. Its packaged `reference-catalogue.bin` was present and byte-identical to the local file (1,442,613 bytes, 6,745 facts; SHA-256 `653e45ee0ff0ff633ed72bda8aa1eec8582f77f661100fe0956e89b58c070ff1`). The packaged atlas `countries.bin` was also byte-identical. Installed Expo FileSystem 19.0.23's iOS `FileSystemFile.text()` and `bytes()` request **write** permission, while ExpoModulesCore grants app-bundle paths **read** permission only; Expo Asset returns the bundled file URI directly. Both native loaders used these methods. This source and packaged-file evidence identifies the bundled-file permission mismatch; the run did not log the caught JavaScript exception. A read-only loader repair and another complete native replay are required. Strict Sweden/France and practice-action assertions remain unchanged.
