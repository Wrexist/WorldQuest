# D1 weekly leagues — local implementation

The weekly league now has a selected-backend implementation rather than an adapter
that always returned null. This serves the learner who chooses friendly competition,
through Profile → League (and the existing Settings toggle). The primary empty-state
action is explicit enrollment. No person search, profiles or messaging is exposed.

## Behavior

- Both `API_ENABLED` and `LEAGUES_ENABLED` must be true. Repository deployment values
  remain false. A session must belong to a verified linked, age-eligible account;
  guests, unknown ages and protected accounts cannot read or join.
- D1 enrollment defaults to opted out. Existing memberships finish their current week
  after opting out; no new week is created. Rejoining cannot change a current cohort.
- Cohorts contain up to 30 real accounts, matched by rank and previous-week active days.
  Assigned curated handles and weekly XP are the only public fields. Zero-XP peers
  are omitted. Your own zero row stays visible without claiming promotion.
- Weekly scores sum server-committed lesson ledger entries. Timestamps are recorded
  inside the SQLite transaction, preventing a request begun before Monday from adding
  an award to an already closed week. Historical rows are not guessed or backdated.
- Cohort closure freezes ranks and pays the existing balance-table podium coins in
  one transaction. Coin ledger IDs use a reserved namespace outside valid lesson IDs.
  Concurrent closure and replay cannot pay twice. Inactive learners hold their rank.
- An hourly bounded sweep settles ten outstanding cohorts per invocation; opening the
  league also settles a learner's previous cohort. Monitor backlog before scaling.
- Account-owned preferences, memberships and results cascade on deletion. Closure
  markers contain only week/rank/activity-band/cohort, no account identifiers.
- The owner-bound API adapter validates responses. Join/settings controls wait for
  confirmation, prevent overlapping writes, and show failure without inventing success.
  All new app copy is English/Swedish. Loading, empty, offline, error and content states
  reuse the existing accessible league screen.

## Deployment and limits

Apply forward migration `0012_leagues.sql` before deploying this Worker. No remote
migration or deployment was performed. Do not interpret a local test fixture as a
live user or an iPhone acceptance result.

Private friend challenges, invite codes, blocking, reporting and moderation are
**not implemented** by this league slice. Leagues have no row interactions or
user-authored names. Friend features must ship their own safety lifecycle together.

The installed iPhone baseline is 1.0.0 (10); this code is not in that installed build.
Physical VoiceOver, background/network recovery, device performance and TestFlight
verification remain open. Public feature enablement is not part of this local change.

## Verification

Real Miniflare/workerd + D1 tests cover consent, eligible-account guards, server-issued
lesson scoring/replays, privacy of returned rows, concurrency, cohort capacity,
rollover, one-time coin payment, opt-out, revoked sessions and deletion cascades.
The existing backend lesson/economy acceptance suite also passes. App tests cover
confirmation-only state changes, repeated taps, failed updates and closed rollout.
Mobile/backend TypeScript, static accessibility checks and the existing economy
simulation pass. Reward values and balance configuration are unchanged.

`scripts/review-leagues.cjs` is a local browser harness backed by real D1. It seeds
verified synthetic accounts solely in its in-memory test database; no fixture/admin
route is added to the app API. Review artifacts live under
`docs/design/reviews/leagues-2026-09-27/`.

Final evidence: six D1 league cases pass, alongside the 32 existing backend acceptance
cases; 18 league UI/control tests, 11 feature-flag tests, 45 Settings tests and 19
league-engine tests pass. The browser report records zero uncaught errors and checks
explicit joining, membership after screen remount, zero-XP display, three viewport
widths, reachable lesson action at 200% text and saved one-tap opt-out. Screenshots
were opened and visually reviewed. Atlas now appears in the navy league header;
an actual first-lesson action fills the zero-XP state without fictional peers.

The connected browser run also exposed an initialization race: the first flag poll
could run before account setup, fail its owner guard, and wait five minutes to retry.
Flag consumers now refresh after account resolution and share concurrent refreshes.
Two new regression tests cover that retry and request sharing.
